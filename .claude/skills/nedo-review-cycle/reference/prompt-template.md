# サブエージェント呼び出しの雛形

`nedo-secretariat-reviewer` を `Agent` ツールで呼ぶときのプロンプト。
`{{ }}` を埋めて使う。**テーマ2の場合は冒頭の上書きブロックを必ず入れること**——
サブエージェントの定義はテーマ1向けに書かれており、そのままだと懸賞金・審査項目・
テーマ記述をテーマ1の行で読んでしまう。

---

## テーマ2用

```
**今回のレビュー対象はテーマ1ではなくテーマ2である。** あなたのシステムプロンプトは
テーマ1向けに書かれているので、以下で対象と物差しを上書きする。

## 対象

`theme2_ライフライン復旧/12_提出版_様式4.md`（テーマ2の提出実体。様式4への転記用原稿）

テーマ2＝「インフラに係る防災・災害対応」。提案の中身は、融雪型火山泥流の計画対象量を
決める「火口周辺の積雪水量」を、光学衛星の多年アーカイブ（Landsat 1984年〜／
Sentinel-2／MODIS）から復元し、年超過確率の分布として砂防事務所に供給するもの。

**懸賞金・審査項目・テーマ記述はテーマ2の行を読むこと。** `koubo/応募要項.txt` と
`koubo/応募申請書_法人応募者用.txt` のテーマ2に該当する記述に読み替えて判定すること。

## 背景

- テーマ1（製油所の保温システム劣化監視）はリポジトリのルートにあり、**提出物は確定済み**。
  今回の対象ではない
- テーマ2は**独立した1件の応募**であり、様式1〜4を1式そろえる
- 字数カウンタは `python3 count_chars.py <file>`（リポジトリのルートにある）

## 既に閉じている指摘

`theme2_ライフライン復旧/review_t2_様式適合.md` に第1〜第{{N-1}}サイクルの指摘
**T-1〜T-{{最後の番号}}** を記録してある。**まずこれを読み、対応済みのものを再指摘
しないこと。** ただし対応済みかどうかの根拠は現物であり、記録の記述ではない。

今回は**第{{N}}サイクル**である。指摘番号は **T-{{最後の番号+1}}** から振ること。

{{本文への指摘が続けて0件なら以下を入れる}}
**第X〜第Yサイクルは本文への指摘が0件で、件数は … と減っている。** 提出物本文は
固まっている。**無理に指摘を作らないこと**——(1)提出物そのものの不備か、(2)提出直前
チェック手順の不備か、(3)それ以上細かくしても実務上の意味がない領域か、を自問し、
(3)なら書かずに「実装可能な指摘: 0件」と言い切ること。**0件と言い切ることは、この工程の
正常な終点である。**

## 直前の変更（今回のサイクルが見るべきもの）

第{{N-1}}サイクルの T-… に対応した。

- {{変更を箇条書きで。これを書かないと古い前提でレビューされる}}

## 併せて見てよいもの

- `theme2_ライフライン復旧/CLAUDE.md`
- `theme2_ライフライン復旧/01_検討経緯.md`（主張の根拠。8.4〜8.8節が現在の案）
- `theme2_ライフライン復旧/poc/out/fig/t2_fig1〜4.png` と生成元 `poc/src/make_figures_t2.py`
- `04_事務局照会文案.md` と `10_提出様式メモ.md`（ルート、両テーマ共通）
- ルートの `12_提出版_様式4.md`（**参照先として正しいかの確認にのみ使う**）

出力はシステムプロンプトのフォーマットに従うこと。
```

## テーマ1用

テーマ1はサブエージェントの定義がそのまま当たるので、上書きブロックは要らない。
対象・既に閉じている指摘（`review_v4_様式適合.md` の N-n）・サイクル番号・直前の変更
だけを渡せばよい。

## 呼び出し方の注意

- `Agent` ツールで `subagent_type: "nedo-secretariat-reviewer"` を指定する
- **1サイクルずつ順に回す。** 並列に複数サイクルを走らせても、対応が挟まらないので
  同じ指摘が重複して返るだけになる
- サブエージェントはバックグラウンドで走る。完了通知が来るまで**同じファイル群を編集しない**
  （レビューアが読んでいる最中に足元が動く）
