# 外部連携の順序 — 誰を、いつ、何を頼んで巻き込むか（両テーマ共通）

3種のレビュー（`nedo-benchmark-reviewer` / `nedo-judge-reviewer` / `nedo-investor-reviewer`）が
**別々の物差しで一致して挙げた唯一の点が「打診0件」**である。そして3つとも「これは本文の書き換えでは動かない」と書いた。
この文書はその1点を動かすための**順序の正本**である。

**`06_協力プラント候補.md` との役割分担**: 06は「**誰に**」の正本（候補・規模・接触ルート・選定理由・出典）。
この文書は「**いつ・何を頼むか**」の正本。**統合しない**——06は候補が増えたら更新し、ここは期限が動いたら更新する。

## 最初に直す前提 ── 06のタイムラインは目的を1つに混ぜている

06の接触タイムラインは「10月上旬に内諾候補と覚書ドラフト合意」を終点にしている。これは**プロトタイプ用の
実データ取得**を目的にした設計であり、**提出物に1行書くための打診とは、期限も依頼内容も別物**である。
混ぜたままだと、目的Aの依頼が1件も出ない（実際に8月10日時点で送付0件だった）。
**【2026年8月12日】この混同を解いたうえで、目的Aそのものを1次通過後に移した**（下の Phase 0）。

| | **目的A: ⑤に1行書く** | **目的B: 実証データを得る** |
|---|---|---|
| 期限 | **10月下旬**（1次結果公表の当日）。**2026-08-12の方針変更で8月24日から移した** | 2026年12月〜2027年3月（実施スケジュールの月別行） |
| 必要なもの | 「1次審査を通過したら検討する」という**条件付きの意向**1件 | 秘密保持契約＋資産台帳＋保全履歴＋対象資産の選定。**加えて「外装張替え履歴」を明示的に頼む**（下の追記） |
| 相手の手間 | メール1往復。担当者の一存で返せる | 法務・情報セキュリティ・現場調整。数週間〜数か月 |
| 提出物への反映 | ⑤「協力先1〜2社での実証」→「**協力の意向を得た**協力先1〜2社での実証」（**+8字**。⑤に枠が既にある）。**※方針変更でこの分岐は使わない**（Phase 2 参照）——提出前に打診しないので、提出時点では意向が存在しない | 提出物には書かない |
| 断られたときの損 | **ゼロ**（本文は現状のまま出す） | 1次通過後にやり直せる |

### 【2026年8月11日追記】目的Bで頼むものの最優先が変わった

**PoC数値監査（`review_v7_PoC数値.md` P-5）で、提案の技術的な分水嶺が
「センサNEdTの実力値（JSI照会）」から「兄弟資産間の放射率の差動経年」に移った。**

- NEdTは**上限性能を一切動かさない**（決めるのは何エポック要るかだけ）。
  したがって**JSI照会の回答が8/31に間に合わなくても提案の骨格の成否は動かない**
- 一方、差動経年は **0.15Kなら二重差分AUC 0.921、0.3Kなら0.788、0.5Kなら0.697** と
  上限を直接決めるのに、**出典が無く実測もされていない**（`poc7_results.json`）

**これは外部の回答待ちではなく、協力先のデータで自前で測れる。**
必要なのは次の3点で、**目的Bの依頼リストの最上位に置くこと**:

| 頼むもの | なぜ要るか | 相手の手間 |
|---|---|---|
| **同一構内の同型ユニット対の識別**（設計・施工年が同じ2系列） | 差動経年を測る対象そのもの。**離隔が数百m以内であることも条件**（`poc6_results.json` の離隔依存: 150-300mで0.43K、2.4-5kmで2.63K） | 台帳を見れば分かる。低い |
| **外装（保温外装板）の張替え履歴の日付** | **「張替え直後＝差動経年ゼロ」の起点が取れる。** これが無いと経年の絶対値が決まらない | CMMSの検索。中 |
| 対象期間の操業カレンダー（負荷） | 負荷変動を差動経年と切り分ける | 既に06の依頼項目に入っている |

**06_協力プラント候補.md の依頼文（「過去の保温点検記録・補修履歴・操業カレンダー」）に
「外装張替え履歴」が明示的に入っていない。** 補修履歴に含まれる想定だが、
**張替えは「補修」と別台帳になっていることが多い**ので、名指しで頼むこと。

**なお目的Aの依頼文は変えない。** 差動経年の測定は目的B（実証データ）に属するので、
条件付き意向の照会に混ぜると法務案件化し、**メール1往復で返る構造が壊れる**（この文書の冒頭の原則）。

**目的Aの依頼文に「データをください」と書いてはいけない。** 書いた瞬間に法務・情報セキュリティ案件になり、
**担当者の一存では返らなくなる**。聞くのは **「1次審査を通過した場合に、貴組織の施設を対象とした検証協力をご検討いただけるか」**
の一点だけである。これは相手にとって拘束力がなく、担当者が上に上げずに返せる。

## 順序

### Phase 0 ── 提出前に出すのは事務局への質問1通だけ

**【2026年8月12日 方針変更】協力候補への打診（A1・A2・A3・A5）と衛星ベンダ照会は、
1次審査の結果が出る10月下旬に移した。提出前に出すのは A4（事務局への質問）1通だけである。**

根拠は3つで、いずれも一次情報で確認した。

1. **1次審査の審査項目5つに、協力先・実証パートナー・チャネルの語が1つも無い**
   （`../50_koubo/応募申請書_法人応募者用.txt` L211-239）。一番近いのが⑤の
   「実用化に向けた想定ユーザー、ステークホルダー、市場ニーズや付加価値等が**示されているか**」で、
   **示されていればよく、確保していることは求められていない。**
2. **審査は「応募書類に基づいて」行われる**（応募要項 III-1）。打診したかどうかは審査の入力に入らない。
   打診が提案書に与える効果は⑤の「協力の意向を得た」**+8字だけ**である（500字の1.6%）。
3. **順位は2027年7月中旬に、開発後の成果物と一般公開のピッチで決まる**（要項 II-1・III-2、`16_優勝の条件.md` 1.1節）。
   1次は通過・不通過を分けるだけなので、**打診が効くのは「1位を取れるか」であって「1次を通るか」ではない。**
   通過が分かってから2027年7月まで9か月ある。

**そして通過後のほうが打診の条件が良い**——「1次を通過した」という肩書がつき、
**事務局の共同研究先の紹介・メンタリング（いずれも1次通過者限定）が使えるようになる**（要項 II-5）。
提出前に自力で当たるのは、制度の踏み台が開く前にわざわざ不利な条件で当たることになる。

**加えて、応募内容の秘密保持について要項に条項が見当たらない。**
協力先に提案の中身をどこまで話すかという判断も、通過後に回したほうが安全である。

> **この変更で失うもの**: ⑤の+8字と、関係構築の2.5か月ぶんの助走。
> 前者は1次の審査項目に対応していない。後者は、提出物の実施スケジュール自体が
> 10月下旬の開始を前提に組まれている（12月・1月のタスキング）ので破綻はしないが、余裕は無い。
> **冬期の現地観測（A2の(2)）だけは年1回しか機会が無いので、10月下旬に最優先で出すこと。**

**理由1（テーマ）: 現在募集中の唯一の回次が当社と無関係なので、そもそも出す先が無い。**
このプログラムは1回次1テーマで、テーマに合致することが応募条件そのものである。第59回の締切 8月25日は
10月下旬より前だが、**出せない回次の締切は例外判断の材料にならない。**

**理由2（回次の周期）: 待っても手遅れにならない。** 告知から締切までが約3週間（第59回は8/4告知→8/25締切）、
回次はおおむね月1回のペースで立つ。**したがって「9月中に確認しておく」必要は無く、
10月下旬に見た時点でその時の回次を判断すれば、逃す回次はその間の1〜2回だけ**である。
インフラ系テーマ（下水道局・水道局）は実在するが**数十回に1回の頻度**なので、
その1〜2回に当たりが来る確率は低く、待ちのコストは小さい。

**加えて、当てにいっていた先はこのプログラムでは取れない。** 06の最優先候補である
**東京二十三区清掃一部事務組合は特別区が設立した一部事務組合であり、東京都の局ではない**ので、
都の各局がテーマを出すこのプログラムのテーマ設定主体に含まれない。
このプログラム経由で届く都関連施設は**下水道局・水道局・環境局が所管する施設**に限られる。
