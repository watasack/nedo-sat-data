## 一次審査での使い方

一次審査は「技術的に本当に成立するのか」を短時間で判断される。図版の並びは
**図0 → 図8 → 図7 → 図9** を先頭に置くのが最も効く。この4枚で
「全体像」「運用時に何がどう見えるのか」「なぜ高分解能でなければ駄目か」
「実データで本当に動くのか」が揃う。残り（図1〜図6）は各節の裏付けとして本文中に配置する。

**KPIや誤差の数字だけでは伝わらない。図8・図9は「地図上で、どの資産が、どう判定
されたか」を直接見せる図であり、審査員が最初に知りたい「で、何が分かるの？」に
一枚で答える。** 図8が設備単位（HotSat-2相当・合成）、図9が複合体単位（実Landsat）で、
2枚は同じ「地図＋判定リスト」の型で揃えてあるため並べて読める。

## 各図の注意点（審査員に突かれうる点）

- **fig6**: AOIは±数百m精度の概略であり現地検証が未了。図の副題と07・08の本文で
  必ずその旨を併記すること。Landsatは昼間パスかつ30m画素なので、これは
  「複合体レベルで手順が通る」ことの実証であって設備単位の実証ではない。
  設備単位はHotSat-2サンプル待ち（09_JSI照会文案.md）。
- **fig7**: 3.5m側はHotSat-2の実データではなく**合成シーンの同条件サンプリング**。
  「HotSat-2相当」という表記を外さないこと。NEdTは両者1K相当で揃えてあり、
  比較の主題は放射感度ではなく空間分解能である旨を本文に書く。
- **fig4右パネル**: TANK04は健全参照ではなく**パッチ注入資産（単発では未検出）**。
  凡例・注記を付録（07の注入真値表）と一致させてある。ここを「参照(健全)」に
  戻すと付録と矛盾するので注意（review_v2 指摘S-1）。
- **fig1**: 各バーのラベルにエポック数を明記してある（単発／二重差分×6エポック）。
  x軸ラベルを「単発観測」に戻すと図内で自己矛盾する（review_v2 指摘L-1）。
- **fig0**: 数値はすべて `poc/out/*.json` から実行時に読み込んでおり、
  PoCを再実行すれば図0の数値も自動追随する（手打ちの数値はない）。
- **fig8**: 地図は poc4 モードBのシーンを**再現**したもの。再現にあたっては
  `poc4_pipeline.py` が poc2ヘッダを exec した後に `rng` を **seed 123** へ貼り替えて
  いる点を必ず踏襲すること（poc2既定の seed 42 のままだと別の乱数シーンになり、
  地図上の資産配置と findings が食い違う）。`poc4_series.json` と完全一致することを
  確認済み。判定区分は action 文の「εアーティファクト」の語で分けている
  （「外装」で分けると UNIT00 の action にも同語が含まれるため誤判定になる）。
- **fig9**: 実データ側には既知の劣化事象がないため、示せるのは
  「健全なものを健全と判定できる＝誤報を出さない」ことまで。**検出能力の実証ではない**。
  図8と対で使い、検出側は合成、誤報抑制側は実データ、と役割を明示すること。
